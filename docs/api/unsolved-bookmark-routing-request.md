# [백엔드 → 프론트] 미풀이 북마크 "풀러가기" 죽은 링크 수정 요청 (단건 풀이 라우팅)

작성: 2026-07-24 / 백엔드 세션
관련: `docs/api/wrong-notes-lightweight-request.md`(경량화 3단계 완료), PENDING.md "미풀이 북마크 익일 죽은 링크"

## 배경 / 문제

아직 풀지 않은 문제를 북마크하면 북마크 탭에 `solved: false`("아직 안 푼 문제") 상태로 남는다.
**익일**이 되면 그 문제는 더 이상 "오늘 세트"가 아니라서, 카드의 "풀러가기"를 눌러도
오늘 문제 화면으로만 이동한다 → **북마크한 그 문제를 풀 경로가 없다(죽은 링크).**

## 결론: 백엔드 변경 불필요 — 프론트 라우팅만 고치면 됩니다

핵심 사실을 코드로 확인했습니다:

**채점 API는 "오늘 세트"로 제한하지 않습니다.**
`POST /api/quizzes/{quizId}/answer` → `QuizService.checkAnswer()` 는 `quizRepository.findById(quizId)`
로 조회할 뿐, `quiz_date` 를 검사하지 않습니다. **어제·그저께 문제도 quizId 만 있으면 지금 제출 가능**하고,
채점·해설·스트릭·잔디가 정상 동작합니다.

즉 죽은 링크는 백엔드 제약이 아니라 **"풀러가기"가 특정 문제가 아니라 오늘 세트 화면으로 보내는
프론트 라우팅 문제**입니다.

## 요청: "풀러가기" → 해당 문제 단건 풀이 화면으로

미풀이 북마크 카드의 "풀러가기"를 **그 quizId 의 단건 풀이 화면**으로 연결해 주세요.
필요한 API는 **이미 전부 배포되어 있습니다.**

### ① 문제 로드 — `GET /api/me/attempts/{quizId}`

미풀이여도 404 가 아니라 200 으로 **마스킹된 상세**를 반환합니다 (검증 완료):

```jsonc
{
  "quizId": 123,
  "category": "INTEREST_RATE",
  "categoryDisplayName": "금리",
  "question": "기준금리를 인상하면...",       // ✅ 있음
  "choices": [ {"id":1,"orderNum":1,"content":"..."}, ... ],  // ✅ 있음 (4지)
  "selectedChoiceId": null,   // 미풀이
  "correctChoiceId": null,    // ★ 마스킹
  "correct": false,
  "solved": false,            // ★ 미풀이 판별
  "explanation": null,        // ★ 마스킹
  "keyword": null,            // ★ 마스킹
  "article": { ... },         // 있음 (nullable)
  "bookmarked": true,
  "solvedAt": null,
  "review": null
}
```

**풀이 화면을 그리는 데 필요한 것(question·choices)은 다 오고, 정답/해설만 가려집니다.**
치팅 방지 설계라 그대로 유지합니다 — 즉 이 응답만으로 "문제 풀기" 화면을 정상 구성할 수 있습니다.

### ② 채점 — `POST /api/quizzes/{quizId}/answer`

오늘 문제와 **완전히 동일**하게 호출하면 됩니다. 별도 파라미터·헤더 없음.

```jsonc
// 요청
{ "choiceId": 2, "elapsedMs": 15300 }

// 응답 (AnswerResponse) — 정답·해설·기사 포함, 오늘 문제와 동일 구조
{ "quizId":123, "selectedChoiceId":2, "correct":false, "correctChoiceId":1,
  "explanation":"...", "keyword":"...", "article":{...} }
```

채점 후에는 오늘 문제와 같은 결과/해설 화면을 재사용하면 됩니다.

## 동작 상세 (프론트가 알아야 할 것)

| 항목 | 동작 |
|---|---|
| **기록 날짜** | attempt 는 **제출한 오늘 날짜**로 기록됨 (과거 소급 아님). 잔디도 오늘 칸에 반영 |
| **스트릭** | 오늘 활동으로 카운트 — 어제 문제를 오늘 풀어도 오늘 스트릭이 이어짐 |
| **재제출 방지** | 이미 푼 문제를 다시 제출하면 **첫 시도만 집계**(`UserService.recordAnswerForUser` 의 `existsByUserIdAndQuizId` 가드). 통계·스트릭 이중 반영 없음 — 프론트가 중복 제출을 막지 못해도 서버가 안전 |
| **정답률 통계** | 첫 시도 기준이라 정상 반영 |
| **북마크 상태** | 풀고 나면 다음 목록 조회부터 `solved: true` 로 바뀌고 "안 푼 문제" 뱃지가 사라짐. 별도 API 호출 불필요 |

## 왜 이 방식인가 (검토한 대안)

| 안 | 내용 | 판정 |
|---|---|---|
| ⓐ 해설 열람으로 전환 | 익일부터 북마크를 해설 카드로 | **기각** — 안 푼 문제의 해설·정답은 치팅 방지로 마스킹하는 게 설계. 북마크가 정답 훔쳐보는 우회로가 됨 |
| ⓑ 지난 문제 풀기 허용(정책 변경) | 이력·잔디 소급 정책 신설 | **불필요** — 백엔드가 이미 지원. attempt 가 오늘 날짜로 찍혀 **소급 자체가 발생하지 않음**(7/18 백필 형평성 이슈와 무관) |
| ⓒ 미풀이 북마크 익일 자동 제거 | 조용히 삭제 | **기각** — "나중에 풀려고 저장"한 사용자 의도를 버림 |
| **ⓓ 단건 풀이 라우팅** | 풀러가기 → 그 문제 풀이 화면 | **채택** — 의도 보존 · 마스킹 정합 · 소급 없음 · 프론트 라우팅 위주 최소 변경 |

## 프론트 작업 체크리스트

1. 미풀이 북마크 카드 "풀러가기" → 단건 풀이 화면 라우팅 (quizId 전달)
2. 단건 풀이 화면: `GET /api/me/attempts/{quizId}` 로 question·choices 로드 (미풀이면 정답/해설 null 인 게 정상)
3. 제출: `POST /api/quizzes/{quizId}/answer` — 오늘 문제와 동일 경로 재사용
4. 채점 후 결과/해설 화면 재사용, 뒤로가기 시 북마크 목록 갱신(`solved: true` 반영)
5. 엣지: 이미 푼 문제로 진입한 경우 풀이 화면 대신 해설 화면으로(서버는 재제출을 무시하지만 UX 상 혼란 방지)
6. 엣지: 삭제된 quizId → `GET /api/me/attempts/{quizId}` 가 404(`QuizNotFoundException`) → "문제를 찾을 수 없어요" 처리 후 북마크 정리 유도
