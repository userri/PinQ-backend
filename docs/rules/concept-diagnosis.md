# 취약 개념 진단 규칙

**SSOT**: `UserStatsService.getConceptStats(Long userId)`
**엔드포인트**: `GET /api/users/me/concept-stats` → `ConceptStatsResponse`

성장 지표(잔디·스트릭·나무)는 `grass-and-streak.md` 를 본다. 이건 진단 로직이라 별도다.

## 1. 카테고리별 정답률

`user_quiz_attempt` 를 카테고리로 묶어 `(total, correct, correctRate = correct/total)` 를 낸다.

- 카테고리가 `null` 인 행은 버린다(유실 데이터 방어).
- `total = 0` 이면 `correctRate = 0`.
- 정렬은 카테고리 enum 이름순 — **정답률순이 아니다.** 화면 순서가 매번 바뀌면 안 되기 때문.

## 2. weakest (가장 약한 개념)

1. 표본 **3문제 이상**(`MIN_ATTEMPTS_FOR_DIAGNOSIS`)인 카테고리만 후보
2. 그중 **정답률 최저**
3. **동률이면 표본이 많은 쪽** — 더 신뢰할 수 있는 진단이므로

후보가 없으면 `null`. 프론트는 이때 진단 배너 대신 "조금 더 풀면 진단해드려요"를 띄운다.

`min()` 이라 **동률이어도 항상 정확히 하나**만 내려간다. 이 점이 화면에서 문제가 된 적이
있다 — 아래 참고.

## 3. 알려진 한계

### 3.1 기간 필터가 없다 (전체 기간 누적)

`countByCategory(userId)` 에 기간 조건이 없어 **가입 이후 전체**를 센다. 최근 추세가 아니다.

그래서 프론트 문구에서 "요즘"을 뺐다(2026-08-05). 최근 추세로 말하려면
`countByCategory(userId, since)` 같은 기간 파라미터가 먼저 필요하다. 그때 창(예: 최근 30일)
안에 표본 3개를 못 채우는 사용자가 대부분일 수 있으니, 창을 도입하면 최소 표본 기준도
함께 재검토해야 한다.

### 3.2 하나만 내려가는데 화면엔 여럿이 같아 보인다

프론트는 정답률을 반올림해 보여준다. 25/43(58.14%)과 7/12(58.33%)는 화면에서 **둘 다 58%**다.
서버가 환율 하나만 `weakest` 로 내려주면 같은 58% 인데 하나만 경고색이 붙어 색이 거짓말을 한다.

**해결은 프론트에서 했다(백엔드 변경 없음)**: 카테고리 목록이 전부 내려오므로 프론트가
**절대 기준(정답률 60% 미만) + 표본 3 이상**으로 직접 판정한다. 경고색과 배너 문구는
**같은 집합**에서 나온다 — 다르게 두었더니 이름 없이 빨간 줄이 남았다. 표현 규칙은
[`../../../PinQ-frontend/docs/ui-rules.md`](../../../PinQ-frontend/docs/ui-rules.md) §6.

**따라서 프론트는 `weakest` 를 쓰지 않는다.** 서버가 상대 기준(`min()`)으로만 고르기
때문이다 — 전부 85% 여도 하나가 내려오고, 동률이어도 하나만 내려온다. 응답 필드는 다른
소비자를 위해 그대로 두되, **화면 판정의 근거로 삼지 않는다.** 서버에서 이 값을 손볼
일이 있으면 프론트가 안 쓴다는 점을 먼저 확인할 것.

→ **`MIN_ATTEMPTS_FOR_DIAGNOSIS` 를 바꾸면 프론트 `ConceptStatsSection.MIN_SAMPLE` 도 같이
바꿔야 한다.** 두 곳에 있는 유일한 값이다.
