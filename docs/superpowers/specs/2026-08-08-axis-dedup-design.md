# 소재 축(axis) 재등장 차단 — 설계

2026-08-08. PENDING "[검수] 소재 재등장 차단 — 프롬프트 이력 포맷 개선 실험 (8/8 승격)" 의 설계 산출물.

## 문제

같은 뉴스 사건이 며칠에 걸쳐 다른 keyword 용어로 재출제된다. 관측 4회 중 3회가 이 유형:

- 엔화 축 6일 4회 — 385(공동 외환개입)·390(엔화 방어)·395(엔 캐리트레이드)·410(경쟁적 평가절하)
- 예금금리 축 당일 2회 — 404(INTEREST_RATE)·406(STOCK)
- [자본 흐름→환율] 4일 간격 — 423↔400 (단, 400 은 용어가 카테고리명이라 8/5 가드 이후엔 생성 불가 표본)

나머지 1회(419↔404 기준금리, 글자까지 동일)는 이 실험 대상이 아니다 — `TERM_GUARD_EXEMPT`
면제 목록이 통과시킨 것으로, 별도 건 (ⓐ). 프롬프트 주입 범위 문제(ⓑ)는 **이미 구현돼 있어**
(`DedupHistory.promptQuestionsFor` 가 `generatedToday` 를 카테고리 무관 merge) 대상이 아니다.

기존 방어선이 못 잡는 이유:

| 방어선 | 단위 | 왜 통과되나 |
|---|---|---|
| 용어 가드 (`TERM_GUARD_DAYS=7`) | keyword 용어 문자열 | 사건이 같아도 용어가 매번 다름 (공동 외환개입 / 엔 캐리트레이드 / …) |
| 렉시컬 검사 | 질문 문장 | 문장이 다름 |
| 프롬프트 이력 `[용어] 질문` + "같은 소재는 각도를 바꿔도 중복" | 모델 판정 | 모델이 보는 소재 = 대괄호 용어뿐. 용어가 다르니 문자 그대로 읽으면 정말 다른 소재 — 지시 무시가 아니라 판정 단위가 어긋난 것 |

## 결정

**axis(뉴스 사건 축) 필드를 신설**하고, 기존 용어 가드와 같은 꼴의 결정적 차단을 axis 축으로
한 벌 더 건다. 인과 축(메커니즘)이 아니라 **뉴스 사건**(예: "엔화 약세")을 축으로 잡는다 —
관측 4건을 실제로 묶는 단위가 사건이고, 검수 로그가 겹침을 세는 단위와 일치하기 때문.
인과 축은 엔화 4건의 메커니즘이 제각각이라 정의상 못 잡는다 (기각).

**핵심 제약 — 사건은 고유명사가 아니다.** 자유 명명이면 같은 사건도 날마다 다르게 적혀
(엔화 약세/엔저 심화/…) 문자열 비교가 원리적으로 무력하다. 그래서:

1. **명명을 재사용 우선으로 강제한다.** 생성 프롬프트 이력 줄을 `[용어 · 축] 질문` 으로 확장해
   최근 axis 표기를 그대로 노출하고, "축이 목록의 사건과 같으면 반드시 그 표기를 그대로,
   정말 새 사건일 때만 새 이름" 을 지시한다. 같은 표기를 쓰면 결정적 가드에 걸리고,
   다르게 표기해 빠져나가는 실패는 자유 명명 방식에서도 어차피 지던 판정이다 —
   실패 표면을 "모델 판정 1회 + 결정적 백스톱" 으로 줄이는 것이지 완전 해결이 아니다.
2. **명명 수렴성을 코드 배포 전에 검증한다** (아래 1단계). 수렴 안 하면 axis 안 기각.
   기각 시 폴백 후보: axis 문자열에 `QuizSimilarityChecker` 렉시컬 유사도 적용.

C안(축 판정 전담 호출)은 비용 +1 call/후보라 기각 — "해설 품질 전담 분리" PENDING 과 묶어
재판단. B안(대괄호 확장만, 차단 없음)은 A안의 부분집합이라 별도 취급 안 함.

## 단계

### 0단계 — 토큰 계측 (선행 배포)

OpenAI 응답 `usage`(prompt/completion/total tokens)를 생성·검증 호출 각각 로그로 남긴다.
현재 어디서도 안 남기고 있어 전후 비교가 불가능하다. **axis 배포 전 기준선을 며칠 쌓는다.**
로그 포맷은 grep 가능하게 고정 (예: `token-usage kind=generate prompt=… completion=…`).

### 1단계 — 명명 수렴성 dry-run (go/no-go 게이트)

과거 30일 발행분에 모델로 axis 라벨링을 돌려 **엔화 4건(385·390·395·410)에 같은 라벨이
붙는지** 본다. 붙으면 성립, 제각각이면 기각. 부수 산출물: 라벨 기준 "차단됐을 건수" —
이게 켰을 때 잃을 발행 수의 상한이다 (개념 포화 충돌의 사전 측정).

- 수단: 읽기 전용 admin 엔드포인트 (DB 무변경, 이력 미등록 — 회귀 하네스
  `POST /api/admin/quizzes/{quizId}/verify` 와 같은 계열). 인증 `X-Admin-Secret` 동일.
- 판정 기준: 엔화 4건 중 **3건 이상 동일 라벨이면 go**. 라벨링도 확률적이므로 1회가 아니라
  2회 돌려 재현되는지 본다.

### 2단계 — axis 필드 + 결정적 가드 (1단계 go 일 때만)

- 생성 응답 JSON 에 `axis` 필드 요구. `quiz` 테이블에 `axis` 컬럼 추가
  (마이그레이션 — prod `ddl-auto=validate` 라 **ALTER 먼저, 배포 나중**, `docs/db-access-and-migration.md`).
- 프롬프트 이력 줄 `[용어 · 축] 질문`, 재사용 우선 명명 지시 추가.
- 저장 전 가드: 같은 axis 가 `AXIS_GUARD_DAYS` 내 재등장이면 폐기. 기간은 1단계 차단 카운트를
  보고 정한다 (기본 후보 7일, 손실 크면 3~4일). **크로스 카테고리 적용 여부도 카운트로 결정**
  (404↔406 유형을 잡으려면 필요하지만 차단 강도가 세진다).
- 기존 발행분은 axis 가 NULL — 가드 실효까지 최대 `AXIS_GUARD_DAYS` 램프. 백필하지 않는다
  (1단계 라벨은 실험용이지 발행 이력 원본이 아니다).

### 3단계 — 효과·부작용 추적 (검수 편입)

- 효과 축: 같은 사건 재등장 (검수 로그 관찰 항목 그대로)
- 부작용 축 1: **발행 수 5/5** (개념 포화 충돌 — 기준 16·용어 가드 추적과 같은 형식)
- 부작용 축 2: **토큰 전후 비교** — 0단계 기준선 대비 증가분을 로그로 확인해 검수 로그에 기록
  (예상 +400/호출 안팎, 이력 줄 라벨 +300 · 지시문 +100 · 응답 필드 +20)

## 하지 않는 것

- ⓐ `TERM_GUARD_EXEMPT` 에서 "기준금리" 등 제거 — 별도 건. 발행 수 직격 위험이 있어
  이 실험과 변수 분리 (방법론: 변수 하나씩)
- 과거 발행분 axis 백필
- 프롬프트 금지 문구 강화 단독 실험 — "지시로는 안 막힌다" (8/5 용어 가드 선례)

## 검증 방법

방법론 메모리(`quiz-rule-experiment-method`) 적용:

- 1단계가 대조군 역할 — 라벨 수렴 실패면 코드를 만들기 전에 기각된다
- 결정적 룰베이스이므로 A/B 가 아니라 **코퍼스 전수 대조** (막혔을 건수 직접 세기)
- 계측 확인: 0단계 로그가 실제로 찍히는지 배포 후 당일 확인, 1단계 엔드포인트는
  알려진 사례(엔화 4건)가 양성 대조군
