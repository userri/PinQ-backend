# [프론트→백엔드] `/api/reviews/today` 에 오늘 집계 노출 요청

작성 2026-08-04. **ALTER TABLE 없음 — 이미 있는 테이블을 응답에 얹기만 하면 됩니다.**

## 문제

복습 완료 화면이 `4 / 4 정답` 을 보여주는데 이건 **세션 기준**입니다.
그런데 "오늘 물 줄 잔디 5개"라는 **하루 단위 목표**를 만들어 놓았으므로 사용자의 단위는 하루입니다.

정원에서 1개 → 세션에서 4개를 풀면 오늘 5개를 다 한 것인데 화면은 4개만 셉니다.
하루 캡(5개)이 들어간 뒤로 **세션은 구현 디테일이지 사용자가 알 단위가 아닙니다.**

## 이미 있는 것

`ReviewDailyLog(user_id, review_date, reviewed_count, correct_count)` 가 이미 있고,
`ReviewService` 가 복습 채점마다 `reviewDailyLogRecorder.record(userId, today, correct)` 로
정확히 갱신하고 있습니다. **필요한 숫자 두 개가 이미 DB에 있습니다.**

> 참고: `ReviewItem` 에 `lastReviewedCorrect` 같은 컬럼을 새로 두는 방안도 검토했으나
> 기각했습니다. (a) 이미 있는 걸 다시 만드는 것이고, (b) "항목은 하루에 한 번만
> 복습된다"는 **규칙 가정**에 기대는 파생값이라 복습 로직이 바뀌면 숫자가 조용히
> 틀립니다. 이번 달에만 stage 리셋 폐기·하루 캡 도입으로 규칙이 두 번 바뀌었습니다.
> `ReviewDailyLog` 는 "그날 몇 번 물 줬고 몇 번 맞혔나"라는 **일어난 사실**이라
> 간격 규칙이 어떻게 바뀌어도 안 깨집니다.

## 요청

`GET /api/reviews/today` 응답에 두 필드 추가:

```json
{
  "reviews": [ ... ],
  "nextDueDate": "2026-08-05",
  "todayReviewed": 5,   // ← 추가: 오늘 복습한 총 개수
  "todayCorrect": 4     // ← 추가: 그중 맞힌 개수
}
```

- 값은 `ReviewDailyLogRepository.findByUserIdAndReviewDate(userId, today)` 에서 그대로.
- 로그가 없으면(오늘 아직 안 함) **둘 다 0**.
- 추가 필드라 하위 호환. 프론트는 Moshi 기본값 `0` 으로 받습니다.

## 프론트가 할 일 (반영 후)

완료 화면을 세션 기준 → 오늘 기준으로 바꿉니다: `오늘 5개 중 4개 정답`.
완료 시점에 이미 `/today` 를 다시 부르고 있으므로(다음 물주기 갱신용) **추가 호출 없이**
같은 응답에서 받습니다.

## 참고 — 함께 고친 것

완료 화면의 `다음 물주기` 가 채점 응답의 **항목별** `nextDueDate` 를 쓰고 있어
"8월 18일"(그 문제의 stage 2 → +14일)이 떴습니다. 백로그가 남아 실제로는 내일인데도요.
프론트에서 `/today` 의 **사용자 단위** 값을 쓰도록 고쳤습니다(`8794206`). 백엔드 변경 없음.
